# Blueprints

A blueprint takes the patterns, scripts, skills, and prompts from the rest of this repo and assembles them into a complete business system.

These are the longest documents in the repo. They are designed to be read once end-to-end, then referenced piece by piece during execution.

## What is in this directory

| Blueprint | What you build |
|---|---|
| [`saas-in-a-weekend/`](./saas-in-a-weekend/) | Build, deploy, and announce a SaaS product in 48 hours |
| [`ai-agency-starter/`](./ai-agency-starter/) | Start an AI automation agency from zero |
| [`content-machine/`](./content-machine/) | Run an automated content pipeline that publishes weekly |
| [`client-dashboard/`](./client-dashboard/) | Build client-facing dashboards that justify a higher retainer |

## How to use a blueprint

1. Read the whole guide before starting. The pieces are interdependent.
2. Block the time. None of these are 30-minute projects.
3. Follow the order. Tempting shortcuts have consequences explained in the guide.
4. When you hit a step that needs another file in this repo, follow the link.

## What blueprints assume

- You have Claude Code, Cowork, or both installed
- You can deploy to Vercel (or have an equivalent)
- You can run TypeScript or Python locally
- You have a GitHub account
- You have a credit card (for SaaS subscriptions, not for fees to the author)

## What blueprints do NOT assume

- That you have an existing business
- That you have a brand
- That you have an audience
- That you have prior experience with any specific tool in the stack

The goal is that someone with an empty machine and an idea can ship.
